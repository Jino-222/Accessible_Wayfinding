계산 기준과 검증 범위

A. 실제 촬영 영상 기반 위치 추정
- NAVER LABS 강남역 B2 공개 이미지. 지도용 자료와 질의를 분리. 지도용 촬영 위치·깊이로 지도를 구성하고 질의 정답은 추정 완료 후 채점에만 사용.
- 한 촬영 세션의 450장 validation을 재사용한 비교이며 독립된 새 시험집합의 성능이 아님. 연속 추적·도착 성공률 평가도 아님.
- 정확한 출력: 위치 오차 0.5m 이하 및 방향 오차 5도 이하. 실패를 포함해 전체 450장이 분모.
- RootSIFT 최근접 매칭 180/450=40.0%, 사전학습 LightGlue 203/450=45.1%.
- 내부 품질 조건을 통과한 수용 후보는 각각 249/329개. 그 중 위치 오차 5m 초과는 91/113개.
- 450장 중 기준 충족 이미지가 23장 증가(약 5.1%p). 학습 모델이 모든 조건에서 더 좋거나 사용자에게 더 안전함을 보장하지 않음.
- CPU 질의 처리시간 중앙값은 RootSIFT 약 0.42초, LightGlue 약 1.99초. 질의·검색·지도 캐시 준비 비용을 양쪽에 포함, 오프라인 모델·지도 초기 로딩은 제외. 휴대폰 지연시간이 아님.
- 별도 test 67장에는 평가 정답이 없어 정확도 미채점. 품질 통과 49/67을 정확도라고 표현하지 않음.

B. Unity 합성 RGB 기반 위치 추정
- 지도 108장, 질의 174장. 렌더링한 RGB의 특징 대응과 PnP로 위치·방향 계산. 질의 정답은 평가용. 알려진 카메라 내부 파라미터·높이 사용.
- 정상 68/69, 상실·복구 70/76, 접근 중단 29/29가 0.5m·5도 이내. 모든 질의를 분모로 포함.
- 정상·복구 시나리오는 가상 접근 지점 도착, 접근 중단 시나리오는 안내 중단.
- 약 22.06m는 역사적 촬영 좌표를 참고한 가상 경로 길이, 현재 시설의 실측 동선 아님.
- 동일 합성 장면의 다른 시점·높이. 카메라 높이 1.2m이며 고유 포스터·안내판이 매칭을 도움.
- 웹 실행 영상은 저장된 추정 결과를 재생. 재생 시간·프레임률을 실시간 모바일 처리 성능으로 해석하지 않음.

C. 웹 직접 이동과 모의 관측
- Three.js의 가상 카메라 위치·방향에서 모의 관측 생성. 이 탭은 RGB 기반 위치 인식기를 실행하지 않음.
- 사용자가 이동·회전하고 위치 관측 상실·재개 및 엘리베이터 접근 중단·재개를 주입.
- 서로 다른 새 관측 3개를 수신한 뒤 안내 재개. 3/3은 수신 횟수이며 영상 재인식 성공 수나 신뢰도 점수가 아님. 상실·중단 중에는 화살표와 남은 거리를 숨김.
- 캡처 순서: 앞으로 10회 이동(16.1m 남음) → 끊김(0/3) → 복구(3/3) → 접근 중단(3/3이어도 안내 숨김).
- 웹 자동 검사 30개는 경로·조작·안내 상태 검사. 인식 정확도나 현장 안전성을 채점한 수가 아님.
- PC 브라우저 직접 조작 및 360/390/430px 화면 폭 검수. 실제 휴대폰·현장·교통약자 사용자 시험 미수행.

공통 한계
- 공개 영상의 엘리베이터와 현재 공식 호기·출구를 전역 좌표로 정합하지 못함.
- 실제 통행 폭·경사·최신 운행 상태를 확인하지 않았으며 실제 이동 안내 서비스로 사용하지 않음.
- 성과 수치의 분모·입력 종류를 합치거나 합성 실험을 강남역 현장 성능으로 표현하지 않음.

D. 향후 AR 서비스 구상
- 스마트폰 카메라 화면의 단계별 AR 안내, 스마트글래스 인터페이스: 후속 개발·검증 목표
- AIGEN 참여 후 목표: 한 역의 시설·좌표 정합 및 유모차 이용자 시험 → 다른 역 등록·갱신 절차 검증 → 전 지하철 확대 검토
- 현재 웹 직접 이동과 실제 모바일·스마트글래스 AR 안내의 구현 수준 구분
- 선행 사례: NAVER LABS 강남역 복층 AR 연구·데모 및 코엑스 네이버 지도 AR 안내. 최초성·경쟁 서비스 부재 주장 없음
